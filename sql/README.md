# Database (db_billet_studio)

You manage the database yourself. The backend creates nothing (`ddl-auto: none`), and Claude only delivers SQL files but never runs SQL.

Target: MariaDB 10.4+ (XAMPP) or MySQL 8.0.16+.

## Initial setup (in this order)

1. Create the database:

   ```sql
   CREATE DATABASE db_billet_studio CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

2. `schema.sql` – all tables (`tbl_roles`, `tbl_users`, `tbl_auth_sessions`, `tbl_models`, `tbl_billets`)
3. `seed_roles.sql` – roles `1 = ROLE_USER`, `2 = ROLE_ADMIN`
4. `seed_models.sql` – model catalog, generated by `tools/asset-pipeline` (idempotent, can be imported again).

In phpMyAdmin: select `db_billet_studio` → "Importieren" (Import) → choose the file. From the console:

```bash
mysql -u root -p db_billet_studio < sql/schema.sql
mysql -u root -p db_billet_studio < sql/seed_roles.sql
mysql -u root -p db_billet_studio < sql/seed_models.sql
```

A new database needs no migrations: `schema.sql` and the seeds already contain them.

`schema.sql` deliberately names no database, so the integration tests (Testcontainers) can load the same file into their throwaway DB.

## Root admin

The root admin is **not** created via SQL. The backend creates it on startup from `ROOT_EMAIL`, `ROOT_PASSWORD` (and optionally `ROOT_NAME`) in `.env.local` or `.env.production` and marks it with `is_protected = 1`. It can be neither locked nor deleted through the user management.

## Timestamps

All `DATETIME` columns hold UTC and are written exclusively by the application. There are no time `DEFAULT`s in the database.

## Migrations (existing database)

Schema changes come as a file of their own in `sql/migrations/<YYYY-MM-DD>_<name>.sql` (e.g. `sql/migrations/2026-10-01_billet_og_image.sql`) and are folded into `schema.sql` in the same commit, so a fresh installation only ever needs `schema.sql` + seeds. Existing databases import only the new migrations, in date order. The header of each file says what it is for, whether it must run before a new backend starts and what works only on MariaDB.

| File | Content | When |
|---|---|---|
| `2026-09-25_model-defaults-cake-globe-champagne.sql` | Catalog: defaults for the cake and the snow globe, rebuilt champagne bottle (file size) | Database with a catalog from before 2026-09-25 |
| `2026-09-26_billet_theme_column.sql` | new column `tbl_billets.theme` (colour swatches in "Meine Billets" (My Billets)), filled from the existing billets | **before** starting a backend from P8 on; without the column every billet request fails |

Both can safely be imported more than once.

The same applies to changes to the model catalog (`tbl_models`, e.g. new scene defaults or a rebuilt GLB): `seed_models.sql` is updated for fresh databases, and in addition there is a small dated migration with exactly the changed rows (`UPDATE`/`INSERT`), so an existing DB never needs the whole seed file again.
