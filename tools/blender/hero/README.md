# Hero build (Blender, headless)

Script-built models for the animated home-page hero. The Python scripts are the source of truth.
Every run starts from Blender's factory startup, builds from scratch and never touches your open
Blender scene.

## Run

```bat
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --factory-startup ^
  -P tools\blender\hero\build.py -- --stage phone --render
```

| Option | Meaning |
| --- | --- |
| `--stage card\|phone\|story\|bake\|export` | what to build. `card` = the card alone, `phone` = card + phone side by side (both checked); the others print "not implemented yet" and exit 0 |
| `--render` | also write Eevee check renders and a contact sheet (`.renders/<stage>/`) |
| `--textures DIR` | real print textures `print_front.png` (A6 portrait) and `print_inside.png` (inside spread, 2:1.41; left half = cover inside, right half = back inside). Default: the orientation test prints in `testdata/` |

Exit code 0 means the build ran and every numeric self-check passed. Any failed check or Python
error gives exit code 1, and `.work/hero.blend` is only saved when the checks pass (an open Blender
that reloads the file on change never sees a broken build).

## Stages

| Stage | Script | Milestone |
| --- | --- | --- |
| `card` | `build_card.py` | H2: folded A6 card, rigid hinge `Card_Hinge`, UVs, materials, checks |
| `phone` | `build_phone.py` | H3: brand-less smartphone, 390:844 screen, `Phone_ScreenDock`, baked AO, checks |
| `story` / `bake` / `export` | `build_story.py`, `bake.py`, `export.py` | H4 (planned) |

Shared helpers (argument parsing, scene reset, materials with nodes looked up by type, image I/O,
Eevee/Cycles setup, studio, cameras, contact sheet, JSON) live in `common.py`.

## Card conventions (details in the `build_card.py` docstring)

- `Card` (empty, origin = bottom of the fold line on the ground) -> `Card_Back`, `Card_Hinge` -> `Card_Front`,
  `Card_Rig` (armature, bones `Spine_00`..`Spine_16`) -> `Card_Spine` (skinned bend strip).
- Open angle phi: `Card_Hinge.rotation_euler.z = -radians(phi)`. 0 = closed, 90 = cover points at
  the front camera (-Y), 180 = flat, cover on the left. Spine bone `kk` follows through a driver:
  rotation about the fold line = `kk/16 * hinge rotation` (in three.js: set it the same way, or play
  a clip in which H4 has baked the drivers).
- Rigid panels + skinned spine: back, spine and cover occupy disjoint angular sectors around the fold
  line at every angle, so there are no overlapping surfaces (no z-fighting), no gaps and no
  interpenetration. Each spine ring is weighted 1.0 to one bone (exact skinning).
- Metres, Z-up. Panels 105 x 148 mm, 0.4 mm card, 0.12 mm edge rounding, spine radius 0.9 mm outside
  / 0.5 mm inside, lens-shaped gap at the spine when closed, V crease valley when open flat,
  0.6 mm mirror-symmetric curl at the free edges.
- Prints run over the rounded cut edges up to 45 deg; the front artwork wraps to the fold apex.
- `UVMap`: prints 0..1 (inside spread: cover u 0..0.5, back u 0.5..1, centre line on the fold apex),
  paper faces in panel units. `UV_AO`: ONE non-overlapping, isotropic lightmap across all three
  card meshes (the materials are shared, so their occlusion texture must hold every mesh).
- Materials `M_Paper`, `M_Print_Front`, `M_Print_Inside`: Principled BSDF only, shared tiled paper
  normal map `images/paper_normal.png` (RGB, 512 px = 60 mm tile, regenerated by every run from a fixed
  seed; the 1-6 mm cockle band has half the H2 slope, so the card no longer looks hammered in raking
  light, and the mottle band is eased from 0.076 to 0.06). The grain is defined in mm (0.1 mm). At 0.117 mm
  per texel the H2 0.05 mm grain cannot be represented. This is accepted: at hero scale a screen pixel
  covers much more card than that, and a smaller tile would repeat the cockle band visibly.

## Phone conventions (details in the `build_phone.py` docstring)

- `Phone` (empty, origin = body centre; rest pose: screen faces -Y, upright along +Z, buttons on +X)
  -> `Phone_Body` (one mesh: frame, black front glass, matte back glass, buttons, camera module,
  flash, USB-C port), `Phone_Screen`, `Phone_PunchHole`, `Phone_ScreenDock`.
- Rear camera: a horizontal rounded rectangle (28 x 13 mm, corner radius 4 mm) in the top corner, with
  two lenses side by side (low metal ring, dark metallic aperture ring, a tinted glass dome with a dark
  pupil) and the flash plus a sensor dot stacked at its inner end. It deliberately avoids the known
  flagship layouts: no vertical capsule with an external flash, no square with diagonal lenses, no
  triangle, no full-width visor.
- Front camera: a 3 mm dark ring with a glossy lens dome, 48 rim samples, 0.05 mm in front of the screen.
- Every phone material has backface culling on, so the glTF `doubleSided` is false (checked on the
  read-back).
- Body 71.0 x 149.0 x 7.9 mm, corner radius 9.5 mm. The display is exactly 390:844
  (67.0 x 145.0 mm, corner radius 7.5 mm) with an even 2.0 mm to the silhouette (0.62 mm metal rim +
  1.38 mm black glass), which is why the body is 0.5 mm narrower and 1.5 mm taller than 71.5 x 147.5.
- `Phone_Screen`: `M_Screen` (black glass, placeholder image on the emission; three.js replaces it with
  a ShaderMaterial), UVMap planar over the full 390 x 844 rectangle. **glTF / three.js contract:**
  `TEXCOORD_0` u = 0..1 left to right, **v = 0 at the top** of the phone (the exporter flips Blender's
  v = 1 at the top). Load the captures with `texture.flipY = false` (the GLTFLoader convention) or
  sample `(u, 1 - v)`. The phone stage reads the GLB back and checks this. The runtime ShaderMaterial
  should output the capture 1:1 (`toneMapped: false` or equivalent). The check renders emulate
  this by inverting the Khronos PBR Neutral view transform on the check image, so display white
  renders as white.
  The screen shares its boundary with the bezel (no overlap). The punch-hole sits 0.05 mm in front of it.
- `Phone_ScreenDock`: centre of the Valentinstag DE `sceneRect` (from
  `tools/asset-pipeline/hero/hero-captures.json`), 0.55 x 1.6 x scale in front of the glass, uniform
  scale = scene-area height / 2.1497. Custom properties `sceneRectDe`, `sceneRectEn`, `screenWidthM`,
  `screenHeightM`, `dockScale` (exported as glTF extras).
  Frame: "local +Z = screen normal, +Y = screen up" is meant in three.js terms, which is the billet
  camera frame. The dock therefore has the identity rotation under `Phone`. In three.js its local +Z
  is the screen normal and +Y the screen up, so a Y-up gift fitted in billet units is added as is,
  with no extra rotation. In Blender its local -Y is the screen normal and +Z the screen up, so a
  Z-up Blender gift stands upright. The GLB read-back checks the three.js axes.
- `UV_AO` lightmap (texCoord 1) on `Phone_Body`, packed with a margin of about 8 px. `images/phone_ao.png` (1024 px, Cycles GPU bake) is wired
  as occlusion through the `glTF Material Output` node group on every body material. The phone stage
  exports `.work/phone_check.glb` and reads it back to verify this.

## Output

| Path | Content |
| --- | --- |
| `.work/hero.blend` | the built scene (gitignored), open it to inspect |
| `.renders/card/*.png` | check renders (gitignored); `spine_tint_*` colour the cover red, back blue, spine green |
| `.renders/card/contact.png` + `contact.json` | labelled contact sheet + legend |
| `.renders/card/checks.json` | numeric self-checks (`passed`, `failures`, dimensions, fold, UVs, overlaps, ...) |
| `.renders/phone/*.png`, `contact.png`, `checks.json` | phone check renders (`front` etc. show the DE light screen capture 1:1, `screen_orientation` the test print, `dock_*` a gift-sized sphere at the dock; the back views add a soft reflector light) + numeric checks |
| `.work/phone_check.glb` | glTF read-back of the phone (checks only) |
| `images/paper_normal.png` | generated paper normal map |
| `images/phone_ao.png` | baked phone AO |

`images/` is the only folder for generated textures; every run checks that nothing else was written
outside `.work/`, `.renders/` and `images/` and that no `__pycache__` exists under `tools/blender`
(`build.py` sets `sys.dont_write_bytecode`).

## Test textures

`testdata/print_front_test.png` (1050 x 1480) and `testdata/print_inside_test.png` (2100 x 1480)
have big labels, up arrows, a grid and coloured corners (TL red, TR green, BL blue, BR amber), so
mirroring or rotation shows at a glance. Regenerate them with:

```bat
node tools\blender\hero\testdata\make_test_textures.mjs
```

(`sharp` is resolved from `tools/asset-pipeline/node_modules`; run `npm ci` there first.)
The committed PNGs are the source of truth: the labels use the installed system fonts (Arial or a
fallback), so regenerating on another machine can change glyphs and bytes, not the layout.
